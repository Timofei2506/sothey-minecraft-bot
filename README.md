# Sothey → luvhi · Minecraft 1.12.2

Однократная ночная передача для **exvxeldo.de5.net:21734**:
**Sothey — 8 часов**, затем **luvhi — 8 часов**, с целевым перекрытием **20 минут**.
`bot1` временно страхует смену GitHub runner. Порт 21734 получен из DNS SRV сервера.

## Хождение вокруг точки — 9 октября 2026

Дополнительно к анимации руки бот проходит несколько блоков вокруг своей точки.
Это обычные пакеты движения игрока: без телепортов, полёта, ускорения и чата.

Правило одно — **радиус**:

| Блок под ботом в момент появления | Радиус |
|---|---|
| Золотая руда | **2 блока** |
| Любой другой блок | **5 блоков** |

Проверок рельефа намеренно **нет**: владелец сделал площадку безопасной, поэтому
бот не сканирует пол и просто ходит в заданном радиусе. Точка берётся из позиции
в момент готовности; если администратор телепортирует бота, она обновляется и
радиус пересчитывается по новому блоку. Хождение останавливается после смерти —
до следующей телепортации администратором.

Управление: `WANDER_RADIUS_BLOCKS=0` полностью отключает хождение,
`WANDER_INTERVAL_SECONDS` задаёт паузу между переходами (по умолчанию 90 секунд).

Хождение **не влияет** на веб-проверку Falix: она подтверждается только по ссылке
в браузере. От кика за простой оно тоже не требовалось — анимация руки уже держала
сессию 4 часа.

## Исправление переподключения — 9 октября 2026

В предыдущем запуске оба клиента одновременно получили `Server closed` в
20:03:52 UTC, затем вошли в `the_end` без подтверждения AuthMe. Старый клиент
ошибочно завершал весь job после 180 секунд ожидания. Причина первоначального
`Server closed` по клиентскому логу не определяется: для неё нужна серверная консоль.

Теперь при пропавшем уведомлении входа выполняется ограниченный `/login`-опрос,
распознаются ответы «уже авторизован», а таймаут пересоздаёт только соединение.
Долгий сбой выводит предупреждение, но попытки продолжаются до исходного дедлайна.
Один `SPAWN`, в том числе в `the_end`, **не** считается подтверждением авторизации.
Неверный пароль, бан и явный запрет доступа по-прежнему останавливают клиента.

Восстановление остатка уже начатого периода: **Resume luvhi until the original deadline**.
Параметр `end_epoch` — исходное абсолютное время окончания, максимум 8 часов вперёд.
Workflow не добавляет новый цикл 8+8. В нём есть статус `minecraft/luvhi` с текущим
подтверждением готовности; при обрыве он сменяется на pending.

**Regression check — reconnect without an auth notice** выполняет реальный контролируемый
реконнект bot1 и намеренно скрывает первое уведомление авторизации. Проверка разрывает
соединение только при наличии другого видимого игрока, чтобы не оставить сервер пустым.

Если хостинг выключил сам Minecraft-сервер, бот не может принудительно включить его
без доступа к панели. Неавторизованное подключение к возможной заглушке не выдаётся за успех.

## Как устроена передача

1. Sothey проходит регистрацию/вход и работает первую 4-часовую сессию.
2. За 2 минуты до её окончания входит **bot1** на 30 минут. Он держит соединение
   на время завершения первого job и запуска второго Sothey.
3. Sothey работает вторую 4-часовую сессию.
4. За **20 минут до окончания второй сессии Sothey** входит **luvhi**.
   Его workflow запускается заранее, но игровой клиент ждёт целевого времени.
5. luvhi работает две сессии по 4 часа. На смене его runner такой же 30-минутный
   вход bot1 страхует разрыв.
6. После второй сессии luvhi всё заканчивается.

У каждого ника отдельная concurrency-группа: два экземпляра одного ника
одновременно не запускаются. Перекрытие разных ников намеренное.

Каждый GitHub-hosted job остаётся короче шести часов. Поэтому 8 часов — это
сумма двух сессий одного ника, а не одна непрерывная задача.
Очередь/сбой GitHub, остановка Minecraft-сервера и серверные ограничения могут
нарушить график; абсолютной непрерывности эта схема не гарантирует.

### Защита от случайного запуска

- Отложенный клиент проверяет через API, что соответствующая исходная сессия
  всё ещё выполняется. Отменённый, завершённый или упавший источник не заменяется
  новым ником для обхода ошибки/бана.
- Отправка нового workflow ограничена текущим репозиторием и повторно проверяет
  уже созданный запуск, чтобы не дублировать его после сетевого таймаута.
- Никакие личные GitHub PAT не нужны во время работы. Задачи передачи и страховки
  используют встроенный `GITHUB_TOKEN` с `actions: write`; остальные имеют права чтения.

## Исправление отключения за простой

Первоначальный запуск сервер остановил сообщением `multiplayer.disconnect.idling`
примерно через 10 минут. Теперь авторизованный клиент раз в 45 секунд отправляет
обычную анимацию руки и меняет выбранный слот. Он не атакует, не ломает блоки,
не пишет в чат и не уходит с места. `BOT_IDLE_ACTIVITY_SECONDS=0` отключает активность.
Используй её только на сервере, где владелец разрешает таких ботов.

При сетевом обрыве клиент переподключается с задержкой 15–120 секунд, учитывая
задержку повторного входа, которую запросил сервер. При смерти он возрождается.
Ошибки пароля, баны, whitelist, captcha и другие явные запреты не обходятся.
Пароли и разговоры других игроков не публикуются в логах.

## Остановка

Открой **Actions** и нажми **Cancel workflow** у всех активных запусков:

- `Sothey 8h → luvhi 8h · 20-minute overlap`;
- `luvhi · handoff from …`, если он уже появился;
- `bot1 · transition bridge from …`, если он уже появился.

Уже вошедший luvhi или bot1 — отдельные workflows: отмена только Sothey
не должна считаться остановкой всех клиентов. Будущие входы ещё ожидающего клиента
отменятся, если проверка обнаружит остановленный источник.

## Учётные данные

Сервер использует offline-mode Minecraft и собственные `/register` / `/login`.
Пароли уникальные и хранятся в **Settings → Secrets and variables → Actions**:

| Ник | Secret |
|---|---|
| Sothey | `MC_PASSWORD` |
| luvhi | `LUVHI_PASSWORD` |
| bot1 | `BOT1_PASSWORD` |

Паролей нет в исходниках или истории Git. Значение созданного секрета нельзя
прочитать через интерфейс GitHub. Изменение секрета не меняет пароль на самом
Minecraft-сервере — сначала нужно согласованно поменять серверный пароль.

Отзови PAT, который был раскрыт при настройке: он не нужен этим workflows,
поэтому отзыв PAT не отключит текущих ботов и не сломает отложенную передачу.

## Проверки

- `Code checks` — синтаксис, **40 тестов**, включая симуляцию повторного входа, аудит зависимостей.
- `luvhi — check or scheduled handoff`, режим **check** — двухминутный реальный
  вход, минимум 60 секунд подтверждённого присутствия после авторизации.
- `Check workflow handoff permissions` — проверяет запуск дочернего workflow
  именно встроенным GitHub-токеном, затем делает короткий реальный тест luvhi.
- `Sothey — manual session`, режим **check** — отдельный короткий тест Sothey.
  Его старый режим **night** запускает только Sothey без новой схемы страховки;
  для основной задачи используй workflow передачи, указанный в начале README.

В логах ищи `AUTHENTICATED`, `READY`, `IDLE_ACTIVITY`, `HEARTBEAT`.
Во второй сессии Sothey должны появиться `HANDOFF_PLAN` и `HANDOFF_SCHEDULED`;
в первых сессиях — `BRIDGE_PLAN` и `BRIDGE_SCHEDULED`.
Короткий успешный тест не означает, что вся будущая ночь уже проверена.

## Локально / VPS

Нужен **Node.js 22 LTS**. Для локальной сессии одного ника:

```bash
npm ci --ignore-scripts
cp .env.example .env
# В .env укажи MC_USERNAME и соответствующий реальный MC_PASSWORD.
node --env-file=.env src/main.js
```

`BOT_RUN_SECONDS=28800` задаёт восемь часов одной локальной сессии.
Локальный `src/main.js` не создаёт workflows и не включает передачу сам по себе.
`reports/status.json` — текущая сводка; папка исключена из Git.

```bash
npm run check
npm test
npm audit --omit=dev
```

Зависимости зафиксированы lock-файлом, Actions — commit SHA.
Override `uuid@11.1.1` закрывает известную уязвимость в транзитивных версиях uuid.
